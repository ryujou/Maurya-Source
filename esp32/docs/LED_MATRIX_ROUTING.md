# 7 路 WS2812 使用 ESP32 内部映射器说明

更新时间：2026-06-12

## 目的

这份文档解释一个关键点：

- **7 路 WS2812 的“换脚”能力，依赖 ESP32-C3 的内部 GPIO matrix / 外设路由机制**
- **7 路 WS2812 的“逐个输出”能力，依赖时分复用扫描**

这两件事不是同一个概念。

换句话说：

- 映射器负责“把 RMT 输出接到哪个 GPIO”
- 扫描器负责“当前轮到哪一路灯条输出”

## 核心结论

ESP32-C3 的内部映射器允许把外设输出路由到不同 GPIO。

因此，低配版的 7 路 WS2812 可以采用：

1. 只保留一套 RMT / WS2812 输出资源
2. 每次只驱动一路
3. 通过内部映射器把该输出临时绑定到目标 GPIO
4. 发送完一条链的数据后，再切到下一路

这就是“一个输出通道，多个 GPIO 轮流使用”的思路。

## 概念拆分

### 1. GPIO matrix

GPIO matrix 的作用是：

- 把内部外设信号接到某个 GPIO
- 或者把某个 GPIO 接入内部外设

对于 WS2812 来说，最重要的是：

- **RMT TX 信号可以路由到指定 GPIO**

这意味着：

- 不需要为每一路 LED 都准备一套独立硬件输出
- 只需要在发送前切换当前输出脚

### 2. RMT

RMT 的职责是：

- 输出符合 WS2812 时序的高低电平序列

它不关心这串波形最终在哪个 GPIO 上出现。

### 3. 时分复用扫描

时分复用扫描的职责是：

- 决定当前发哪一路
- 决定当前路的数据从哪个 buffer 取
- 决定发送顺序和切换节拍

## 推荐工作模式

建议把 7 路 LED 的输出过程抽象为：

```text
buffer[0] -> route to GPIO0 -> send
buffer[1] -> route to GPIO1 -> send
buffer[2] -> route to GPIO3 -> send
...
buffer[6] -> route to GPIO21 -> send
```

也就是说：

- **数据源是 7 份 buffer**
- **物理输出是 1 套 RMT 逻辑**
- **GPIO 是轮流切换的**

## 为什么要这么做

### 好处

1. **省资源**
   - 不需要 7 套独立硬件输出逻辑。

2. **代码更清晰**
   - “换脚”和“换数据”都在一个统一的调度层里处理。

3. **低配版足够用**
   - 7 路、每路少量灯珠的场景，完全适合这种方式。

4. **和现有工程兼容**
   - 可以保留现有效果层和协议层，只改灯驱动抽象。

### 代价

1. **不是并发输出**
   - 任一时刻只能有一路在发。

2. **需要 reset 间隔**
   - WS2812 在一条链发送完成后，需要满足 latch/reset 时间。

3. **更依赖软件调度**
   - 扫描节拍和路由切换要稳定。

## 建议的软件职责划分

### 扫描调度器

负责：

- 当前扫描到第几路
- 这一路的 GPIO 是什么
- 这一轮输出结束后切到下一路

### 路由管理器

负责：

- 配置 RMT 输出当前绑定到哪个 GPIO
- 在需要时切换路由

### Frame Buffer 管理器

负责：

- 保存 7 路的 LED 数据
- 提供写入和读取接口
- 不关心具体输出到哪个 GPIO

## 推荐接口思路

### 路由切换

```c
esp_err_t led_route_select(uint8_t channel);
```

表示当前准备把 RMT 输出切到某一路。

### 写 buffer

```c
esp_err_t led_buffer_set_pixel(uint8_t channel,
                               uint16_t index,
                               uint8_t r,
                               uint8_t g,
                               uint8_t b);
```

### 扫描发送

```c
esp_err_t led_tdm_scan_step(void);
```

表示执行一次“当前路由 + 当前 buffer + 当前链输出”。

## 与灯效层的关系

灯效层不应该知道“GPIO matrix”这件事。

灯效层只需要：

- 计算灯效结果
- 写进 buffer

扫描层再把 buffer 送出去。

这意味着：

- 灯效逻辑可以复用
- 高配版和低配版可以共用同一套上层算法
- 以后改 GPIO 只动硬件层，不动效果层

## 与当前低配版工程的关系

当前低配版的推荐架构是：

- `LOW_VERSION_IO_MAP.md` 定义固定引脚表
- `LED_TDM_DESIGN.md` 定义 buffer 和扫描抽象
- 本文件定义“ESP32 内部映射器怎么参与扫描”

三者关系是：

- IO Map：告诉你有哪些脚
- TDM Design：告诉你数据怎么组织
- Matrix Routing：告诉你数据怎么输出到脚

## 实现时的注意事项

1. **不要把扫描和路由硬编码到灯效函数里**
   - 灯效只写 buffer。

2. **不要把 GPIO 切换散落在各处**
   - 统一放在路由管理层。

3. **不要假设 7 路会同时发**
   - 实际上是轮流发。

4. **要保证每路发送完后有足够 reset 时间**
   - 否则 WS2812 可能把前一帧当成未结束帧。

## 结论

ESP32-C3 的内部映射器提供了“RMT 输出切到不同 GPIO”的能力；
时分复用扫描提供了“7 路数据轮流发送”的能力。

两者结合后，可以实现：

- 一套 RMT 输出资源
- 7 路独立 WS2812
- 每路可单独配置灯珠数量
- 上层只写 buffer，不直接管物理输出

这正是低配版最适合的结构。
