# Maurya v1.8.2-jp BLE OTA対応書き込みツール

## 操作手順

1. Maurya ESP32-C3コントロール基板を1台だけ接続します。
2. `Maurya_JP_Flasher_v1.8.2-jp.exe`をダブルクリックします。
3. シリアルポートが1つだけ表示されていることを確認し、「書き込み開始」を押します。
4. 全消去を確認し、「書き込み完了」と表示されるまで待ちます。
5. 基板を取り外し、次の基板を接続します。

本ツールは旧レイアウトを全消去し、デュアルスロットとアプリBLE OTAに対応したレイアウトへ移行します。既存の無線モードとライト設定は初期化されます。このUSB移行後は、Wi-Fiへ切り替えずにMauryaアプリからBLEだけで更新できます。

書き込み完了には、ESP32-C3であること、フラッシュ容量が4 MBであること、4つのイメージのSHA-256と書き込み検証が正常であること、再起動後のUSBシリアルModbusデバイスアドレスが1であることのすべてが必要です。

## 初期設定

- BLEデバイス名：`Maurya-XXXX`（末尾はデバイスのMACアドレスから生成）
- Wi-Fiアクセスポイント：`Maurya-XXXX`（BLEと同じ末尾）
- Wi-Fiパスワード：`Maurya123`
- GPIO4スイッチがOFFの場合、起動直後に消灯してディープスリープへ移行します。

## 注意事項

- 書き込み時にフラッシュ全体を消去するため、以前の設定は復元できません。
- 一度に接続できる基板は1台だけです。
- Python、ESP-IDF、インターネット接続は不要です。
- 実行ファイルには商用コード署名を付与していないため、Windows SmartScreenが警告を表示する場合があります。
- 詳細ログは実行ファイルと同じ場所の`logs`フォルダーに保存されます。書き込み権限がない場合は`%LOCALAPPDATA%\MauryaFlasher\logs`に保存されます。

## エラーが発生した場合

- 「デバイスが見つかりません」：USBデータケーブル、ドライバー、基板の電源を確認し、「デバイスを再検出」を押してください。
- 「複数のデバイスが見つかりました」：他のESP32デバイスを外し、基板を1台だけ接続してください。
- 「フラッシュメモリーの実容量が4 MBではありません」：この基板は本バージョンの対象外です。書き込みを続行しないでください。
- 「USBシリアルModbusから応答がありません」：基板を接続し直して再試行してください。解決しない場合はログを開発担当者に渡してください。
- エラーが1件でも発生した基板は、合格品として出荷しないでください。

## 開発者向けビルド情報

単一実行ファイルはesptool 5.3.0とPyInstallerで生成します。`build_release.py`が固定イメージ、マニフェスト、SHA-256を実行ファイルへ内蔵します。リリース後にBINファイルを手動で差し替えないでください。
